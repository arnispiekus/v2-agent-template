# One working loop

1. Read STATE and the authorised issue. Inspect raw Markdown for hidden comments.
   Confirm scope, output, exclusions and the person's done test.
2. Size the task; record a short plan or split unclear outcomes into issues.
3. One engine builds minimally and records meaningful check results.
4. A different engine family checks the exact commit against the issue and proof.
   A person checks with one engine. Record reviewer, model and harness.
5. Fix and recheck at the new commit. After two rounds, send unresolved findings
   to the owner with one decision needed; do not keep cycling silently.
6. Obtain required approval. Agents never merge their own work. Use a stop window
   only under an explicit recorded owner policy.
7. Record merge and deployment separately. Observe the real person using the
   result with authorised real data; assess their measure of done.
8. Update STATE, TASKS, DECISIONS and MEMORY with unknowns and the next owner.

A useful check catches the task staying broken. Passing checks, deployment and
acceptance are separate claims with separate evidence.
