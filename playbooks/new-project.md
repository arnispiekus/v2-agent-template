# Start and size a project

1. Ask who it is for, what they need and how they will judge the result.
2. Size before planning. A bounded edit with an obvious check needs a short task.
   A connected behaviour change needs a short plan. Several independent outcomes
   need separate issues with explicit dependencies.
3. Copy the seven project files. Agree GOAL, reference inputs, figures, exclusions
   and acceptance owner. Keep unknowns visible.
4. Compare the smallest workable approaches. Record the chosen trade-off in
   DECISIONS and obtain owner approval before building beyond agreed scope.
5. Use one issue list. Give the first issue a done test, output and owner.
   Record the next action and owner-only action in STATE.
6. Choose builder, independent checker and merge policy. Check setup and access
   without copying credentials into files.

The sizing step adapts the method attributed in [NOTICE](../NOTICE.md).
