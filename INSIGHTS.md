# Five habits

## 1. Say who reviewed
What: Record reviewer, model, harness and exact commit.
Why: A review needs clear independence and scope.
How to check: Match its receipt to the current commit before approval.

## 2. Fix the reference figures before tuning
What: Agree inputs and expected figures before adjusting behaviour.
Why: A moving reference can hide errors behind an improved-looking result.
How to check: Run a code-repository check against the agreed figures.

## 3. Integration, deployment and acceptance are separate steps
What: Record merged, live and used with distinct evidence.
Why: Success at one step does not demonstrate success at the next.
How to check: Require dated receipts and the person's acceptance.

## 4. Checks that cannot be skipped
What: Put required checks on the merge path and enforce the chosen policy.
Why: Optional checks cannot reliably protect a shared outcome.
How to check: Inspect active rules and exercise a failing disposable change.

## 5. One issue list as the backlog
What: Keep work in one issue list and link from project notes.
Why: Competing lists obscure priority and ownership.
How to check: Match every active task to one current issue and owner.
